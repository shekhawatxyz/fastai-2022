# Architecture v2 — executable, self-revising world knowledge
2026-11-25. Design contract, not an implemented model or measured result. Preserve E1–E17. No toy SOTA or new GPU claim.

## Why this target
Primary target: WorldTest / AutumnBench, ICML 2026 (https://proceedings.mlr.press/v306/warrier26a.html). 43 interactive environments, 129 tasks: masked-frame prediction (MFP), change detection (CD), planning (PL). Reward-free exploration, then separate behavioral tests. Paper appendix F.2 reports Opus 4.6 overall 39.9% (MFP 44.2%, CD 19.8%, PL 55.8%); human 90.2%. o3 CD 22.2%. These are published comparators, not a verified current world record; check newer results before declaring SOTA. Primary aim > strongest matched overall result; 50% overall is a research target, not an empirical forecast. CD and MFP jointly are the first diagnostic because they test prediction and revisability without conflating planner quality. WARC/MechEval remains independent validation of cross-mechanic sample efficiency. Do not use the privileged Autumn program oracle as a learning baseline. Read the official environment, prompt and agent code: https://github.com/BasisResearch/MARAProtocol/tree/main/python_examples/autumnbench ; interpreter https://github.com/BasisResearch/Autumn.cpp . Its LLM agent consumes observations/action history and scratchpad to choose actions. Use official interfaces/scoring without handing hidden simulator programs, task answers, coverage instrumentation or latent state to our agent.

## Texts that change the design (not claims that ancient authors specified ML)
- Patañjali, Mahābhāṣya Paspaśāhnika, §§50–53, Joshi/Roodbergen translation: rejects word-by-word enumeration in favor of general and particular rules. Teaching, retention and use matter; learn a compact generative model with explicit exceptions, not a lookup table. https://pdfcoffee.com/patanjali-s-vyakarana-mahabhashya-paspasha-ahnika-ed-tr-s-d-joshi-j-roodbergen-poona-1986-600dpi-lossy-pdf-free.html
- Bhartṛhari VP 1.35 and 2.152: practiced expertise is not fully communicable by explicit rules. Keep a learned perception/proposal/prediction channel even when executable schemas exist. https://www.wisdomlib.org/hinduism/book/vakyapadiya-of-bhartrihari/d/doc1216481.html ; https://www.wisdomlib.org/hinduism/book/vakyapadiya-of-bhartrihari/d/doc1239259.html ; https://doi.org/10.1080/09608788.2022.2074365
- VP 1.83–85, 2.314–316, 3.7.63/104, 3.8.4–5: provisional parts, contextual meaning, event-relative roles, whole actions over moments. Do not identify a concept with a color, a fixed embedding slot, or a single frame. See ARCHITECTURE.md and E17 for translations.
- Later grammarians Kauṇḍabhaṭṭa and Nāgeśa discuss semantic compatibility and mutual expectancy rather than accept Bhartṛhari's unitary view wholesale. Maintain compositional and holistic hypotheses; constraints should eliminate impossible bindings rather than require every symbol to have a single fixed denotation. https://plato.stanford.edu/archives/spr2021/entries/language-india/
- Nyāya's learning by paired presence/absence and insertion/removal, Gaṅgeśa's investigation of unrecognized conditioning factors (upādhi), and tarka: choose controlled contrastive interventions and use failures to propose missing conditions, not just increase weight updates. https://plato.stanford.edu/archives/sum2025/entries/early-modern-india/ ; https://plato.stanford.edu/archives/win2021/entries/gangesa/ ; https://seop.lovelace.illc.uva.nl/entries/gangesa/
- Earlier jñāpaka and apoddhāra leads remain in E13. These schools disagree; the proposed engineering mechanisms are extrapolations.

## One system, not independent heuristics

```
immutable event log <------------ actual observations
        |                                 ^
        v                                 |
perception + learned proposals ---> experiment/action
        |                                 ^
        v                                 |
probabilistic executable concept graph -> predict / plan
        ^          |                      |
        |          v                      |
        +---- contrast, revise, refactor -+
        |
       pretrained search prior (source worlds only)
```

Primitive = a partially specified event relation over participants, context and time. It can be a neural predicate or a typed executable relation, with uncertainty, not necessarily a discrete token. Concepts are variables in a theory; a concept can take other concepts as arguments. The graph is a set of competing theories, not a single forced hierarchy.

### Data contract and minimal modules
* Event: immutable (episode, t, observation_before, action, observation_after, reset flag). During prediction only pre-action history is visible. For masked/changed test tasks follow exact official test protocol; no updates using answer feedback unless protocol permits them.
* Perception: extract candidate connected components, tracks and spatial relations using scipy.ndimage and scipy.optimize.linear_sum_assignment; retain raw grid and multiple plausible segmentations. Small Torch convolutional/attention encoder for object/event embeddings; optionally WARC when doing ARC. Do not force grouping of disconnected objects; propose group hypotheses.
* Schema: immutable typed AST (variables, predicate, guard, effect, duration/termination, uncertainty, evidence IDs). Primitive operations: equality, adjacency, position/relative displacement, presence/absence, set operations, arithmetic and state updates. No per-game concepts or hidden mechanics. A composition can call learned schemas with bound arguments, and a parameterized higher-order schema can accept existing schema IDs as operands. Executable dependencies acyclic within a time step; temporal recurrence explicitly bounded. Use dataclasses, NumPy, NetworkX dependency DAG, cached canonical AST hashes and vectorized evaluation. Do not build custom tensor kernels, solver or graph library.
* Theory particle: a library of schemas, event-to-schema/participant assignments, parameters and log weight. Maintain beam of 16 rival theories initially, including neural-only fallback. Event evidence belongs to raw log, not exclusively to the first hypothesis.
* Proposal policy: start with generic contrastive edits and anti-unification of existing explained event ASTs. Edits: insert/remove guard, add role binding, split exception, merge compatible relations, promote repeated subevent to callable schema, abstract repeated subprogram with variable predicate/operation, re-segment temporal interval. Source-trained neural ranker later proposes/ranks edits from event embeddings and prediction residual. Keep enumeration fallback; record candidate counts.
* Neural dynamics: small action-conditioned attention model, predict next grid and action-conditioned latent event embeddings; retain residual for unexplained effects. Use target encoder EMA + anchored grid/object prediction to resist collapse; mask whole object/events on source tasks as in Causal-JEPA, not random pixel-only masks. PyTorch AdamW initially; tune lr and weight decay on source validation only; compare Muon+AdamW on identical data/budget before claiming gain. Fixed source pretraining episodes and compute across ablations. Source tasks generated independently of benchmark hidden programs; no target labels/solutions in training. On WARC use official checkpoint folds and full TTT recipe.
* Inference: for each theory, assign event participants via bounded candidate bindings (Hungarian assignment as initial proposal, beam for relational ambiguity), execute enabled rules and use residual for uncovered effects. Weight competing theories by evidence, retain independent explanations. Predict mixture of complete event trajectories, not mean of incompatible categorical frames. Use held-out development calibration for weights.
* Structural learning: on contradiction, retrieve matched prior events (positive AND negative) using current bindings, propose candidate edits, evaluate affected subgraph on immutable raw history. Recompute event assignments under new meanings. Discover reusable relations by anti-unification, then rewrite existing explanations to refer to that relation; permit learned relation arguments in later induction. Reject revisions whose gain does not cover complexity and validate prospectively. Keep a null/independent model to limit negative transfer; do not overwrite historical scores. Rebuild from scratch with same final language as an oracle comparison to separate representation benefit from search-path benefit.

## Explicit learning objective and control
For theory G and log D, minimize code length L(G)+L(assignments|G)-log p(D|G), including neural residual likelihood; code length counts typed AST tokens and bindings under a fixed prefix code learned only on source training. Penalize unsupported structure; full model averages posterior weights over the retained theory particles. During online search do not count the same observations twice after re-indexing: replace likelihood contributions for affected events. Fit/evaluate old observations is structure search, not held-out evidence. For causal generalization, evaluate prospective forecasts and unseen compositions. Compare identical graph with no retroactive re-binding, identical library learner with full-history conventional inference, fixed vocabulary, and flat/neural models. If the stronger ordinary method achieves the same result, say so.

Exploration: pick an action or short reset/replay contrast that disambiguates plausible predictions on *reachable* scenes. Score expected reduction in predictive loss on a fixed distribution of reachable probe states, minus action/reset and compute cost. Approximate by simulating the beam; ordinary outcome entropy, random and standard information gain are controls. E9 already falsified semantic MI alone; do not resurrect it. Include noops, action reversals and one-variable-at-a-time changes, but never inspect hidden environment state or future test questions to choose exploration. A new representation can reveal that two past events were controlled contrasts; it then changes future probe selection. At test, use calibrated predictive option likelihood for MFP, sequential likelihood-ratio surprise calibrated on source validation for CD, and beam/BFS or MCTS over predicted states for PL. Plan under uncertainty and replan after actual feedback if allowed. No privileged simulation.

## Minimal implementation order and gate
1. Integrate official MARA runner as an external evaluator; expose only public observations, action choices and permitted rewards. Pin upstream revisions, dataset checksums; verify scores on upstream random agent and exact simulator oracle separately. Unit test prediction-before-observation, no test code access, ambiguity, reset, unchanged events, execution termination, re-binding equivalence, cached vs full likelihood, action budgets.
2. Implement CPU flat event/transition learner and ordinary library/refactoring baseline first, then full graph. Reuse E6 AST discovery, E13/E16 posterior coupling, E14 fallback, E17 event templates; keep previous failures as regression tests. Train a small neural baseline and neural proposal prior on same source data, with matched optimizer and ensemble compute. No unnecessary framework.
3. Freeze a development subset and an untouched validation/evaluation policy before model selection. Report official 129-task aggregate only when running complete official protocol, not cherry-picked task scores. Public tasks can be contaminated by development; require a disjoint external suite/fresh tasks for generalization. Compare strong LLM agent and conventional WorldCoder-style synthesis under same interaction allowance; record differing compute/API costs explicitly. Three seeds, bootstrap paired environment deltas (not independent frames), per-family scores and wall time. Profile cProfile + torch.profiler, log search counts, peak RAM, prediction/update timing, source training budget and inference budget.
4. CPU pass gate proposed for preregistration before execution: full model improves strongest matched CPU baseline by >=5 absolute points overall, paired environment-level interval above zero, no family degradation >2 points, and beats the best verified published matched-protocol result before calling it SOTA. Target >50% overall, not a forecast. A competitive CPU result on a single family permits diagnostic GPU training only if it demonstrates architectural gain against equivalent strong controls; user decides actual GPU spend. No GPU prediction based on synthetic runtimes. WARC transfer test remains mandatory corroboration, not a score substituted for Autumn.
5. Required assets: official AutumnBench data (download via MARAProtocol scripts/download_dataset.sh), interpreter build/wheel; upstream LLM baseline may need API access. For WARC use held-out checkpoints and recording archive. Authoring runtime has not loaded these assets or run this architecture. A code review is not a reproduction.

## Prior art most likely to subsume us
DreamCoder (library + learned search), WorldCoder (executable world models + exploration), ExoPredicator (predicates and temporal process discovery), OPINE-World (ontology revision), Causal-JEPA (object masking), Schema Networks (causal compositional generalization), and conventional Bayesian theory induction/experiment design. https://doi.org/10.1145/3453483.3454080 ; https://proceedings.neurips.cc/paper_files/paper/2024/hash/820c61a0cd419163ccbd2c33b268816e-Abstract-Conference.html ; https://www.basis.ai/blog/exopredicator/ ; https://arxiv.org/abs/2607.01531 ; https://proceedings.mlr.press/v306/nam26c.html ; https://proceedings.mlr.press/v70/kansky17a.html . Candidate contribution: jointly learn new *event-level conceptual operands* and re-bind prior evidence under those operands to change subsequent discovery and experimental design. This is not established novelty; matched ordinary library learning + belief revision may subsume it. A negative result is meaningful. Do not substitute cultural attribution for scientific evidence.
